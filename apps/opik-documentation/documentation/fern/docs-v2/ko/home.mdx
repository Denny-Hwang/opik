Opik은 LLM 애플리케이션의 동작을 이해하고, 성능을 측정하며, 체계적으로 개선하도록 돕는 [오픈 소스](https://github.com/comet-ml/opik) 플랫폼입니다. 챗봇, RAG 파이프라인 또는 다단계 에이전트 중 무엇을 구축하든 Opik은 "내 노트북에서 작동한다"는 단계에서 "프로덕션에서 안정적으로 작동한다"는 단계로 나아가는 데 필요한 도구를 제공합니다.

## Opik 사용 방법

<Tip>
  **Claude Code, Cursor, VS Code Copilot, Codex 또는 opencode를 사용하고 있나요?** [Opik MCP 서버](/mcp-server)를 설치하면 채팅에서 트레이스를 읽고, 출력에 점수를 매기고, 프롬프트를 저장하고, 실험을 실행하는 등 전체 워크스페이스를 제어할 수 있습니다.
</Tip>

<Steps>
  ### 애플리케이션의 동작 확인

  Opik은 모든 LLM 호출, 도구 실행 및 에이전트 단계를 기록하므로 어떤 출력이 만들어진 전체 과정을 살펴볼 수 있습니다. 코드 몇 줄만 추가하면 모든 요청과 응답의 완전한 로그를 얻을 수 있습니다.

  [트레이스 기록 시작하기 →](/tracing/getting-started)

  ### 트레이스로 테스트 스위트 구축

  문제가 있는 트레이스를 발견하면 테스트 케이스로 전환하세요. [Ollie](/ollie)에게 문제를 설명해 자동으로 만들거나 UI 또는 SDK를 통해 테스트 케이스를 추가할 수 있습니다. 그런 다음 Ollie 또는 SDK로 테스트 스위트를 실행해 수정 사항을 검증하세요.

  시간이 지나면서 가상의 예제가 아니라 실제 프로덕션 장애를 기반으로 테스트 스위트가 성장합니다.

  [첫 번째 테스트 스위트 구축하기 →](/evaluation/advanced/building-test-suites)

  ### 프로덕션 품질 추적

  수신되는 트레이스에 자동으로 점수를 매기는 온라인 평가 규칙을 설정하고 프로젝트 대시보드에서 피드백 점수, 지연 시간, 비용 및 오류율을 모니터링하세요.

  [프로덕션 모니터링 설정하기 →](/production/online-evaluation/rules)

  ### 프롬프트 자동 개선

  Opik의 최적화 알고리즘은 수동 시행착오 없이 지표와 데이터셋을 기준으로 다양한 프롬프트를 테스트해 가장 효과적인 프롬프트를 찾습니다.

  [첫 번째 최적화 실행하기 →](/development/optimization-runs/quickstart)
</Steps>
